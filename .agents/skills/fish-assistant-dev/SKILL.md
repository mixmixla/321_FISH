# 摸鱼助手（321_FISH）开发

## 定位与源码依据

这是 Windows 桌面局域网 IM + 桌游项目：Tkinter 客户端、自建加密 TCP Hub、
内嵌网页 HTTP(S)/SSE、文件与媒体通道。Excel 是客户端工作表模式，不能据名称
误判为 Office 插件、网页项目或 Excel 文件处理任务。

当前机器入口是 `D:\Project\321_FISH`；优先使用当前任务明确指定的仓库，
以 `COLLABORATION.md`、`run.py`、`client_core.py`、`games_pkg/` 确认身份。
旧路径或暂存副本不是新的默认工作区。

开始前读取当前 `AGENTS.md`、`COLLABORATION.md`、`README.md` 和已有
`PROJECT_MEMORY.md`，核对 Git 分支、状态和相关差异。用户当前要求、仓库现状
优先于本技能快照；不要把未提交功能当成远端主干已发布。
缺少项目记忆时按源码继续，不为不存在的文档阻塞；需要时再建立记忆。

按任务加载必要参考：

- 定位功能、追接口、增加协议或桌游：[项目与数据流地图](references/project-map.md)。
- 环境、测试、打包、GUI/音频问题：[开发与验证](references/development.md)。
- 聊天状态、权限、工作表、并发及既有修复：[关键约束与排错](references/invariants.md)。

## 改动方式

- Windows 命令用 PowerShell 7 (`pwsh`)，沿用当前 `.venv` 与 `.python-version`；
  不因系统旧 Python 的 PATH 优先级而替换别的项目环境。
- 按功能追踪 `ChatWindow → ClientCore → MsgType/Hub → TCP/HTTP/SSE → UI`。
  根据实际需求同步有关端和测试，不凭一端的函数名生成平行协议或状态存储。
- UI 留在 Tk 主线程；业务读写/解码在 worker，通过事件队列和 `after` 回到 UI。
  不从后台线程创建/销毁 Tk 图片、字体、变量，不去掉 `tkguard` 而只掩盖崩溃。
- 新 UI 发送消息沿用统一发送逻辑，保留私聊/群聊/密聊、引用、编辑、草稿、只读
  频道以及 pending/failed 状态。Excel 本地格子值不等于服务器消息正文。
- 游戏规则、房间生命周期、双方 UI 是不同层；按项目地图查需要联动的层。
- 遵循仓库的 `feature/` / `fix/`、提交格式和 PR 约定；主干禁止直接 push。
  若当前已有任务分支和未提交改动，保留并延续，不重新初始化或强制拉取覆盖。

## 验证与交付

使用项目 `dev.ps1` / `.venv\Scripts\python.exe run.py`。先验证相关功能，
完成行为改动后按协作规范跑全量门禁；GUI 改动另验证真实窗口、最小尺寸、
键盘/鼠标交互和换肤。语法通过、测试全跳过或截图漂亮不能替代交互验证。

默认回归使用合成媒体，真机摄像头与截图比较需要对应显式选项；普通网络测试
不能为便利打开真实麦克风。遇到卡住的用例先读取日志/目标测试调用栈，不反复
启动整套测试或中断无关进程。验证脚本见参考，不复制易污染账号偏好的旧 smoke。

交付说明改动、验证、实际限制及本地/已发布状态。持久维护仓库
`PROJECT_MEMORY.md` 的事实与当前工作，按代码证据更新本技能中受影响的参考。
不要把测试计数、分支名或一次故障永久写成每轮必须相同的条件。

## 数据边界

当前仓库已公开；管理员凭据从部署侧配置，禁止提交实际密码。不要把 `prefs.json`、聊天历史、审计、运行状态、TLS 私钥或真实
下载文件复制进技能、截图、提交或共享包；配置值按需求在受控环境读取，不把
口令/令牌值写入文档。技能本身不增加推送、合并、发布、开设备或修改外部系统
的授权；沿用当前用户已明确授权的范围。
