## 2. 检修清单（按"能不能发布"排序）

> 每条统一格式：**症状 → 根因（文件:行）→ 修法 → 验收判据（不变量）→ 回归测试**

### 🔴 P0 · 发布阻断项（不修不能给同事用）

#### P0-1 固定管理员凭据
- **症状**：公开仓库里带着可登录的管理员凭据；改密接口对管理员**主动拒绝**。
- **根因**：`config.py:144` `ADMIN_PWD = "L57"`（**3 字符**）、`config.py:290`、`server.py:424` `_admin_nick` 默认 `"L57"`、`server.py:425-426` 建哈希、`server.py:1572-1573` 校验、`server.py:1618-1619` 拒绝改密。
- **修法**（缺一不可）：
  1. **删掉默认常量**。改为首次启动初始化：口令由部署者设置（写进 `server_state/`，或环境变量 / 命令行必填），**不设默认值**。
  2. **未初始化时拒绝以管理员身份登录**，并在日志/控制台明确提示"请先初始化管理员凭据"。
  3. **迁移**：为已有部署提供一次"旧默认口令 → 新口令"的强制改密路径；发布说明里写清"用默认凭据跑过的部署必须换口令"。
  4. **移除改密白名单**（`server.py:1618-1619`）—— 管理员也应能改自己的口令。
  5. 管理员**昵称**默认值一并去掉（`server.py:424`）。
  6. 纠正文档：`README.md` / `INVITE_FRIEND.md` / `COLLABORATION.md` 里"仓库为私有、放心传"之类说法（报告已指出）。
- **验收判据**：
  - 仓库全量 grep **搜不到任何默认口令/昵称字面量**；
  - 未初始化凭据时，**以管理员身份登录必须失败**且日志可读；
  - 改密后**旧口令立即失效**；
  - **正样本对照**：正常设置/改密流程仍可用（防止"把功能整没了"当成修好了）。
- ⚠️ **边界**：把仓库改回私有 **不能** 替代这一步（历史与已分发的副本里仍带着凭据）。

### 🟠 P1 · 公共链路（不修，每款游戏/每个功能都会重复踩）

#### P1-2 文件传输：先鉴权、后变更
- **症状**：已认证但**不是该传输参与者**的用户，只要知道有效 `file_id`，就能破坏别人的传输状态。
- **根因**（三处同型）：
  | 处理 | 位置 | 问题 |
  |---|---|---|
  | 拒绝 | `server.py:5178` → `5181` `pop` | `pop` 在 `5182` 身份校验**之前** |
  | 校验回执 | `server.py:5236` → `5240` `pop` | 同上 |
  | 取消 | `server.py:5247` → `5250` `pop` | **之后完全无身份校验** |
- **修法**：抽出**单点守卫** `_xfer_of(sess, fid, roles)`：`get` → 校验 `sess.uid in (rec.sender_uid, rec.receiver_uid)`（按动作区分允许的角色）→ **通过后**才 `pop`/改状态。三处都走它（**三处各写一份必然再次漂移**）。
- **验收判据（不变量）**：
  > **被拒绝的请求，不得改变任何传输状态。**
  实现方式：请求前后对 `self.xfers` 做**逐键快照比对**，非参与者的请求必须**完全相等**。
- **回归测试**：三方夹具 —— A 发起、B 接收、**C 乱入**调用 reject / verify / cancel，断言 A↔B 的传输仍完好。

#### P1-3 会话退出语义：「关闭一个端」不该误伤同账号其他端
- **症状**：同账号开两个客户端，关掉其中一个 → **另一个端的文件传输被取消**、**另一个端被踢出正在进行的游戏**。
- **根因**：`server.py:1962`（`_drop_xfers_of(sess.uid)`）与 `1969`（`rooms.on_disconnect(sess.uid)`）**按 uid 无差别执行**；而同一函数的 `1965` 才做"最后一端"判断、`1967` 语音房走了它。
- **修法**：把"是否最后一端"抽成单点（如 `_is_last_session(uid)`），让**传输 / 游戏 / 语音**三处统一口径。
  - 若产品上**决定**"游戏与传输按账号语义"（即关掉任一端就退出游戏），那就**写进文档并在 UI 上显式提示**——但不能保持"静默不一致"。
- **验收判据（不变量）**：
  > **关闭一个端，另一个端的传输与游戏状态不得改变**（或：按文档声明的一致语义改变）。
- **回归测试**：同账号双端夹具（两个 session 同 uid），关 A 断言 B 的传输表与房间成员表**不变**。

#### P1-4 游戏结束 → 自动回大厅（`Timer` 传参错误）
- **症状**：一局打完后**永远不回大厅**；再次开局走的是"重置"路径。
- **根因**：`server.py:6330`
  ```python
  threading.Timer(3.0, _reset, daemon=True).start()   # ← Timer 没有 daemon 形参
  ```
  `daemon=True` 被当成 `args` ⇒ 3 秒后在线程内调用 `_reset(True)` ⇒ `TypeError`（`_reset` 定义在 `6323`，零参数）⇒ **异常只在子线程里，无人可见**。
- **修法**：
  ```python
  _t = threading.Timer(3.0, _reset)
  _t.daemon = True
  _t.start()
  ```
- **验收判据**：
  - 结束一局后 **3±0.5 秒内** `room.status` 回到 `CREATED` **且** `room.gs is None`；
  - 该 Timer 触发的异常**必须能让测试失败**（依赖 §3 的子线程异常捕获）。
- ⚠️ 这条**必须和 §3 一起做**：否则现在的测试体系**看不见**这个 bug，修了也证明不了。

#### P1-5 开局可重复调用
- **症状**：对局进行中，房主再点"开始" ⇒ **当前对局被静默重置**。
- **根因**：`games_pkg/rooms.py:106-118` `start()` 只校验"是不是房主""人数够不够"，**没有 `status` 守卫**；`115` 直接重建 `room.gs`，`117` 递增 `round_no`。
- **修法**：
  ```python
  if room.status != RoomStatus.CREATED:
      raise GameRuleError("本局进行中，请先结束本局")
  ```
- **验收判据**：`PLAYING` 期间调用 start 必须**抛错且 `room.gs` 与 `round_no` 均不变**。

#### P1-6 随机种子可预测
- **症状**：知道**房号 + 轮次**就能算出种子 ⇒ 牌堆/身份分布可被完整复现。受影响的是**所有隐藏信息类**：谁是卧底、狼人、一夜狼、阿瓦隆、说谎者、UNO、21 点、小丑牌。
- **根因**：`games_pkg/rooms.py:170-176`
  ```python
  def _seed_for(self, room): 
      return int(room.room_id[1:]) * 1000 + room.round_no     # R1 第 1 轮 ⇒ 1001
  ```
- **修法**：
  - **生产种子**改由服务端不可预测来源派生（`secrets` / `os.urandom`），随对局生成并只在服务端持有；
  - **测试固定种子**走独立入口（显式传 `seed`），**与生产路径分开**（报告原话：把正式对局的随机源与测试用固定种子分开）；
  - 考虑把 seed 一并纳入 `audit` 日志，便于事后复现争议局（**不影响安全性**，因为日志不下发给客户端）。
- **验收判据**：同一房间连续两轮开局的 `gs.rng` 首值不同；且**仅凭公开信息（房号、轮次、快照）无法推出** `private(uid)` 的内容。

#### P1-7 11 款游戏无桌面操作路径
- **症状**："有规则、有画面"，但**确认不了能操作**。
- **根因（精确数据）**：`client.py:11031 _GAME_ACTIONS` 共 **30** 项；`client_gameui.py:786 _CLICKS` 共 **20** 项。下列 11 项**两条都不在**：
  `kaituo 开拓` / `lingdi 领地` / `tielu 铁路` / `gongfang 工坊` / `chengzhu 我是城主` / `gemcity 璀璨宝石` / `siji 四季物语` / `bolan 波兰大选` / `azul 花砖物语` / `yahtzee 快艇骰子` / `nimmt 牛头王`
- **修法**（先判定、再分类，**不要直接判死**）：
  1. 逐项排查**是否存在第三条入口**（通用控件 / Web 端 / 快捷键）；
  2. 分类为 **a) 补接线** 或 **b) 标为实验**（`_GAME_META` 加 `desktop_ready=False`，不进默认大厅显示）。
- **验收判据**：每款游戏**要么**有可执行的桌面动作路径，**要么**有显式的"未就绪"声明。**不接受"没接线但看起来能玩"。**

### 🟡 P2 · 单游戏规则缺陷

#### P2-1 UNO：座位索引当 UID 传入
- **根因**：`uno.py:111` `self.hands = {u: [] for u in self.players}`（**键是 uid**）；`260-265` `_give_cards(uid, n)` → `self.hands[uid].append`；但
  `196` `nxt = (self.current_idx + self.direction) % len(self.players)` 是**座位序号**，
  `195` `self._give_cards(nxt, 2)`、`199` `self._give_cards(nxt, 4)`、**`141` 还有一处**同样把它当 uid 传。
- **后果**：给**错的玩家**发牌；若座位序号不是合法 uid ⇒ `KeyError` 直接崩。
- **修法**：`self._give_cards(self.players[nxt], 2)`（三处）。
- **验收判据**：3 人局出 `+2` / 万能`+4` 后，**只有下家**手牌增加对应张数，其余人**逐张不变**。
- **回归测试（关键）**：夹具里**故意让 uid 不等于 0..n-1**（例如 uid = 1001/1002/1003）—— 否则座位序号与 uid 恰好重合，测试会**假绿**。

#### P2-2 拉密：拒绝的请求污染桌面
- **根因**：`rummikub.py:117` `_extend`：
  ```
  128  self.table[row] = new            # ← 先改状态
  129  self._apply_rack(uid, ids)       # ← 后校验手牌，72 行会 raise("没有这些牌")
  ```
- **修法**：把 `_apply_rack` 的**持有校验**先做成只读检查（不修改），全部通过后再写 `self.table[row]`。
- **验收判据（不变量）**：非法接续被拒后，`self.table` 与请求前**逐元素相等**。

#### P2-3 围棋：桌面点击协议不匹配
- **根因**：`go.py:100` 读 `action.get("x")/("y")`；而 `client_gameui.py:788` 把围棋交给 `_click_move`，后者发 `{"fx","fy","tx","ty"}`。
- **后果**：**围棋桌面端点棋盘必失败**（抛「坐标必须为整数」）。对照组 `chess.py` / `xiangqi.py` 读的正是 `fx/fy/tx/ty` ⇒ `_click_move` 对它们正确，**只有围棋错配**。
- **修法**（推荐前者）：
  - **a)** 给围棋单列 `_click_go`：单击即 `submit({"x": c[0], "y": c[1]})`；
  - b) 让 `go.act` 兼容 `x/y` 与 `tx/ty` —— **不推荐**：规则层不该迁就 UI 的字段命名。
- **验收判据**：桌面端点空点能落子、点已有子报"该位已有子"、越界报"越界"；**且 `x/y` 与 `fx/fy` 不再混用**（可加静态检查）。

#### P2-4 你画我猜：`ended()` 恒返回 None
- **根因**：`games_pkg/drawguess.py:116-117` `def ended(self): return None` ⇒ 没有整场结算。
- **修法**：**先拍板产品语义**（这是产品决策，不是技术决策）：
  - 若定位 **"有总局结算"** ⇒ 补 `ended()`，达到局数后返回结构化结果；
  - 若定位 **"连续休闲轮次，本就不该有整局"** ⇒ 在 `_GAME_META` 显式标注 `has_match_end=False`，UI 不显示"本局结束"，也不进"能否打完一局"的旗舰筛选。
- **验收判据**：声明与实现一致（有结算就能返回结果；声明无结算就**不许**出现"结束"提示）。
