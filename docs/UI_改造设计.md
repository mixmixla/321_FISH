# 摸鱼助手 UI 改造设计文档

> 对标 QQ / 微信 / Telegram · 2026-09 · 状态：分析定稿，动工待令

***

## 1. 项目定位

**一句话**：做一个"微信的克制 × QQ 的会话骨架 × Telegram 的技术血统与干净 UI × 内嵌桌游 × 摸鱼安全"的局域网工具。

**现状**：技术内核已达 QQ 级（加密握手、P2P 文件直连 + 断点续传 + MD5、7 款桌游、群聊、网页端、审计、双 EXE），但 UI 停留在"功能按钮堆叠"——本质是**功能驱动开发 vs 产品驱动开发**的差距，而非能力不足。

***

## 2. 现状审计（UI 十维度差距）

| 维度      | 当前实现                      | QQ/微信/TG            | 结论          |
| ------- | ------------------------- | ------------------- | ----------- |
| ① 会话体系  | 无会话列表，在线名单+群两个 Listbox 混排 | 会话列表、未读红点、置顶、最后消息预览 | **最大短板**    |
| ② 消息呈现  | Text 控件纯文本，3 色区分          | 头像+气泡+昵称+时间戳+引用     | 大短板         |
| ③ 身份头像  | 无，纯昵称                     | 圆形头像/群头像            | 可做          |
| ④ 未读与通知 | 无红点无提醒                    | 红点角标、通知             | 可做          |
| ⑤ 表情    | 文字短代码                     | 大表情/GIF             | 中           |
| ⑥ 文件消息  | 一行进度 Label                | 文件卡片+打开目录           | 中高          |
| ⑦ 图片/语音 | 无                         | 图片消息/语音条            | 协议层工作量      |
| ⑧ 群功能   | 建群/成员列表                   | 公告/@/管理员/踢人         | 需扩协议        |
| ⑨ 搜索    | 无                         | 全局搜索                | 中（JSONL 可搜） |
| ⑩ 视觉质感  | 9pt 灰字无留白                 | 现代布局圆角层次            | **纯重构**     |

**归因分层**：① 摸鱼隐秘是刻意设计约束（非失误）；② tkinter 是平台天花板（无动画引擎，但"办公 IM 观感"可达）；③ 前几轮迭代全在堆功能，UI"能跑就收手"是投入分配问题。

***

## 3. 对标结论：学什么、弃什么

### Telegram（技术同源，UI 主要参照）

- **学**：桌面版左右分栏；主题系统（自定义配色+深色，Token 化架构）；消息状态（已读双勾/编辑/双向删除）；会话文件夹；群权限分级；2GB 无损文件哲学（与我们的 P2P 同源）

- **弃**：默认聊天非 E2EE 的边界（我们 README 已诚实声明，未来 1v1 表情指纹比对为升级路径）；bot/频道/话题等大而全；被墙与无国内生态；媒体缓存膨胀

### QQ（会话骨架）

- **学**：会话列表范式（置顶/未读红点/最后消息/时间）；群功能深度（公告/@/管理员）

- **弃**：臃肿商业化（广告/装扮商城/直播）；高辨识度外观（摸鱼必死）

### 微信（克制美学）

- **学**：极简主义（低信息密度/留白/单一强调色）；气泡语言（左灰右绿/时间戳弱化）

- **弃**：克制过头（**文件会过期**是硬伤，绝不学）；PC 版残废；历史不同步

### 我们保持领先的

- P2P 文件直连+断点续传（优于 TG 中转、碾压微信过期）

- 聊天+桌游一体化（三者皆无）

- 摸鱼安全工程（双 EXE/假 Excel/热键，对手做不到）

- 审计留痕（企业级能力，个人 IM 没有）

***

## 4. 双皮肤架构（解决"质感 vs 隐秘"根本矛盾）

不是两套代码，是**一套 Token 化主题系统**（颜色/字体/显隐开关），皮肤 A/B 共享同一批组件（会话列表、气泡、卡片）。

| <br /> | 皮肤 A「内部办公助手」 | 皮肤 B「畅聊模式」     |
| ------ | ------------ | -------------- |
| 场景     | 上班默认         | 休息/热键切换        |
| 头像/气泡  | 无头像、文字流      | 色块头像+左右气泡      |
| 红点/通知  | 全隐藏、无声       | 红点+时间线+通知      |
| 配色     | Office 灰蓝    | 微信式绿白 / TG 式蓝白 |
| 识别度    | 像内网 OA 工具    | 像聊天软件          |

参考实现：tdesktop `window/themes/`（配色方案加载）+ `chat_theme.cpp`（聊天壁纸/主题应用）。

## 5. 改造蓝图 R1/R2/R3

### R1 · 视觉与信息架构（纯 client.py，不动协议，风险最低）

- **会话列表**：数据模型从"频道+名单"升级为"会话对象"（单聊/群聊/系统/游戏 × 最后消息/未读数/置顶/时间）

- **消息渲染**：Frame 气泡（左他人/右自己）+ 首字色块头像 + 时间分隔线 + 昵称 + 右键菜单

- **Token 主题系统**：皮肤 A/B 的基础设施（色板/字体/间距常量 + 皮肤开关）

- **整体留白、圆角、层次**

- 涉及：`client.py`（ChatWindow 重构）、`config.py`（主题 Token）、新增 `theme.py`

- 验收：无协议改动；81 测试不回归；聊天/游戏/文件三界面视觉统一

### R2 · 消息能力（协议小幅扩展）

- 图片消息（缩略图内嵌+点击放大，协议新增 image 帧）

- 文件卡片化（现有 xfer 事件 → 卡片：名称/大小/进度/打开目录）

- 引用回复（reply 字段）、本地搜索（JSONL 全文检索）

- 涉及：`protocol.py`、`server.py`、`client_core.py`、`file_client.py`、`client.py`

### R3 · 通知与沉浸

- Windows 通知/任务栏闪烁/免打扰

- 深色模式（主题系统第三套 Token）

- 双皮肤热键切换（并入现有 HotkeyManager）

- 群权限分级（管理员/踢人/退群，需扩协议）

- 涉及：`hotkey.py`、`client.py`、`server.py`、`protocol.py`

### 7.4 主题配色（day-blue / night-green 调色板）

| Token                | 浅色(day-blue)  | 深色(night-green) | 用途       |
| -------------------- | ------------- | --------------- | -------- |
| `windowBg`           | `#ffffff`     | `#282e33`       | 窗口背景     |
| `windowFg`           | `#000000`     | `#f5f5f5`       | 主文字      |
| `windowBoldFg`       | `#222222`     | `#e9e8e8`       | 加粗/标题    |
| `windowSubTextFg`    | `#999999`     | `#82868a`       | 次要文字     |
| `dialogsTextFg`      | 同 subText     | `#8d939e`       | 会话末条消息   |
| `msgInBg`            | `windowBg`(白) | `#33393f`       | 对方气泡     |
| `msgOutBg`           | `#def1fd`     | `#2a2f33`       | 自己气泡     |
| `msgInBgSelected`    | `#bbe1fc`     | `#009687`       | 选中态      |
| `historyScrollBarBg` | `#00000040`   | `#8989897a`     | 滚动条      |
| `msgServiceBg`       | `#00518059`   | `#363c43c8`     | 日期/系统消息底 |

**Telegram 配色哲学（与微信差异）**：对方消息 = 窗口白底（无独立色），自己消息 = 浅蓝（#def1fd）；深色模式下自己比对方略深（#2a2f33 < #33393f）。左轻右重，读起来主次分明。

### 7.5 基础令牌（basic.style）

- 正文字号 `fsize`：**13px**

- 通用大圆角 `roundRadiusLarge`：6px；小圆角 `roundRadiusSmall`：3px

- 主题文件格式：`key:#rrggbb;` 键值文本（`.tdesktop-theme`），深色 = 换一套值 → 我们的 `theme.py` 直接采用此格式

### 7.6 tkinter 落地映射

| tdesktop 能力        | tkinter 方案                                               | 难度 |
| ------------------ | -------------------------------------------------------- | -- |
| 圆角气泡/徽章/头像         | Canvas 自绘圆角矩形 + 椭圆裁剪                                     | 中  |
| 62px 会话行 + 46px 头像 | Canvas 绘制整行（含未读角标、时间）                                    | 中  |
| 阴影 2px             | 无原生阴影 → 用 1px 边框 + 外衬色模拟或舍弃                              | 低  |
| 滚动条 12px 圆角 3px    | ttk.Scrollbar 定制或自绘                                      | 低  |
| 主题切换               | `theme.py` 读 `key:#rrggbb;` 文本 → apply 到 Token 变量 + 全量刷新 | 中  |
