## 0. 项目定位（长期愿景）

1. **一个账号，多端互通**：桌面端（Tkinter）+ 网页端 + 安卓端 使用同一账号体系、同一聊天/桌游/好友数据。
2. **聊天中枢**：群聊、私聊、密聊、E2EE、文件/语音/视频、朋友圈、任务待办。
3. **桌游大厅**：40+ 款桌游统一封面艺术、统一对局框架、支持新桌游插拔。
4. **办公伪装**：Excel/VSCode/Terminal/PPT/Mail 多皮肤，老板键静默摸鱼。
5. **可运营**：账号管理、审计、云端历史保留、服务器运维面板。

平台与账号的打通是「大软件」的地基，所有里程碑都围绕它推进。

## 1. 协作方式

两人（**mixmixla** 与 **Siiyou**）协作开发，无固定分工——**谁有空谁做**，任务按需认领。为避免两人同时改同一大文件（`client.py` / `web.py` / `server.py`），动手前先 `git pull`，在任务清单里「认领」当前任务并在沟通过程中互相知会撞车。

> 通用约定：核心改动（协议 / 加密 / 账号）改动后双方互相 review；合并进 main 前测试全绿。

### 4.3 游戏内部组件美术图（全新接入，桌面 + 网页同步）

接入机制（通用，先做这一层，**桌面 + 网页同步**）：

### 4.5 音效 + 动画特效机制（对局体验层，桌面 + 网页同步）

现状：**通用 UI 音效/动效已有，但桌游对局专属的音效与动画特效没有统一机制层**。
- 音效：`widgets/ui_fx.py` 有 `click()`（按钮点击叫 Beep）与 `set_sound(on)` 总开关；客户端另有消息提示音（`notify_sound` 四档）。这些都是 **UI/消息** 音效，**不是桌游对局专属 SFX**（落子/吃子/出牌/结算/胜利等），也没有音效资源文件管理（现在全是在线 beep）。
- 动画：`ui_fx.py` 有按钮渐变/按压/淡入通用动效；个别 games_pkg（uno/siji/lovelove/dou/balatro）已有判决类动画，且有既定规范「纯函数 painter 动效 + 时间推导 + 粒子 ≤48 封顶」。但**无统一对局动画框架**（落子轨迹 / 出牌飞入 / 结算粒子 / 胜利庆祝多数棋类未接，且零散不成层）。

统一音效层（**桌面 + 网页同步**）：
- [ ] 音效资源管理：建 `assets/sfx/`，统一格式（建议 `.wav`），按场景命名（`move.wav`/`capture.wav`/`deal.wav`/`win.wav`/`tick.wav` 等）；补齐 `winsound`/音频播放封装，支持后台播放与开关（复用 `set_sound` 语义）
- [ ] 桌面端对局音效接入：统一给棋类/卡牌类挂「落子/出牌/吃子/结算/胜利」音效；在不同伪装皮肤下仍可被老板键静默（沿用 `_boss_active` 抑制惯例）
- [ ] 网页端对局音效接入：用 WebAudio 对齐同一套核心音效（可降级静音），与桌面端按键场景一一对应
- [ ] 音量/主题联动：对局音效走统一开关 + 音量，桌面与网页语义一致、与消息提示音一致可配置

统一动画特效层（**桌面 + 网页同步**）：
- [ ] 对局动画框架抽象：抽一层「落子/出子/结算/胜利」统一动画入口（沿用纯函数 painter + `time.monotonic` + repaint 续帧 + 粒子封顶的既定规范；网页端用 CSS/Canvas 对齐同名动画），先选一款旗舰游戏（建议璀璨宝石/中国象棋）桌面 + 网页同步接入验证
- [ ] 通用特效库：落子回弹、出牌飞入、吃子消散、结算彩带/胜利粒子（粒子数按组件数量取模锚点 ≤48，避免性能问题——见项目教训）；桌面 Tk 与网页实现共用同一套「动画触发语义」
- [ ] 大厅卡片动效：封面加载淡入、卡片 hover/选中反馈（桌面 + 网页同步，与 4.4 大厅交互衔接）
- [ ] 动画性能保障：动画不影响掉帧/滚动，多子桌游（围棋/军棋）特效封顶；桌面 headless 下纯函数可测，网页端帧率可观测
- [ ] 安卓端（后续，M5）复用同一套音效资源与本动画语义（Flutter 自绘）

> 验收：旗舰游戏接完动画特效 + 音效后，桌面端 + 网页端各跑对局冒烟截图；纯函数动画单测覆盖「时间推导 / 粒子封顶 / 无动画保底」，双端共用断言。

## 9. 安卓端技术选型（已定：Flutter 原生）

> **决定（2026-09-30）：安卓端采用 Flutter 原生开发。** 选择理由：Flutter 自定义绘图/动画（对局棋盘、封面、暖粉主题）与现有 Tkinter 桌面端视觉理念契合；一套代码后续可扩展到 iOS/桌面。

| 项 | 方案 |
| --- | --- |
| 框架 | **Flutter（原生 Dart UI）** |
| 语言 | Dart |
| 通信 | 复用现有 TCP 加密协议 + `protocol.py` 帧（X25519+AES-256-GCM 语义），Dart 侧用 `cryptography` 包对应实现 |
| 状态/路由 | Riverpod + go_router（M0 内选定） |
| 目标平台 | Android 首发（后续可扩 iOS/桌面） |
| 与桌面关系 | 视觉/语义对齐现有桌面端，不承诺像素级一致 |

> 前提：M3 的 web.py **仍保留**（作为桌面端外轻量网页入口 / 局域网快速访问），不改动。安卓与桌面是两套独立 UI，共用同一服务器协议与账号服务。
