# UX-01 设计规范草案 v1

2026-10-04。来源：[Prompt v1.1](../后续开发Prompt_UX-TRIAL-01.md)。
交互高保真原型：[两套聊天/大厅方向](UX-01-directions.html)。目前是设计原型，不是应用截图或用户审美验收。

## 旧界面问题与选择

依据 UX-TRIAL-01 的 15/16/17/19/20/22 原图：聊天左栏占比过大、工具与消息争抢空间；
正文过小、颜色偏淡、粗细层级不足；Excel 外壳和聊天皮肤拼接；大厅窄列卡片与大片空白割裂；
混用 emoji、默认按钮、渐变封面、薄边框与半透明窗口，阅读容易受背景干扰。
这些不是单独替换色值能解决的问题。

主控选择 **A「雾岸」**：左侧固定导航、会话列表、主要内容三层；工作场景以柔和中性色和灰绿强调，
游戏封面用低饱和棋盘图案。B「纸间」使用顶部导航、暖白与深墨色、编辑式不等宽卡片，
休闲辨识度较强，但改变现有 Tk 布局的成本和小窗口密度压力更高。收到用户反馈时可调整，当前不等待逐项批准。

## 核心页面实施约束

- 登录：持续标签、首次绑定说明、字段错误、连接目标、提交中状态；不改变认证规则。
- 聊天：导航约64–80px，会话栏约220–260px并可收窄；消息区占主要空间；输入独占一行，附件/图片常驻，低频命令进入有名称的“更多”。
- 设置：连接/外观/通知/快捷键/账号与数据按任务分组；主动禁用和注册失败分别呈现；保存与错误反馈持续可见。
- Excel：现代办公工作簿样式、清晰公式栏与标签页；保留真编辑、选区、Enter本地保存/Ctrl+Enter发送；顶部与发送区明确目标，长正文支持适宽/换行/全文。
- 大厅：两旗舰优先，搜索/人数/支持状态筛选；同一状态源映射47款，不支持给具体原因；原型“实验”不升级为稳定。
- 棋盘/房间：棋盘为中心，玩家/执色/回合/观战/等待/不可操作原因完整；统一红金棋色和形状辅助；最后一手/胜线/结算/上局摘要/再开可发现。
- 窗口：默认完全不透明；透明作为可选且覆盖子窗；最小/普通/最大和可用DPI分别验证；关闭、收起、恢复与退出文字一致。
- 空态/加载/离线/错误/成功：给一句原因和一项可执行操作；不能因没数据留下无解释空白。

## 性能与独立验收

继续 Tkinter 与现有内嵌 Web。复用布局、字体和图标缓存；不引入浏览器内核或持续高帧率背景动画。
Tk布局用pack/grid与内容约束，不把原型CSS像素机械搬进绝对坐标；画布仅承载必要图标/棋盘/消息。

实际 UI 实施后同合成数据/同尺寸记录旧版与新候选各自源码/EXE身份；“同版”指新截图确属受验的新候选，
前后必然跨源码版本，必须分别标识。覆盖登录、聊天、设置、Excel、大厅、棋盘、结算。
独立审查逐页评估层级/比例/排版/色彩/间距/图标/状态/操作可发现性，明显粗糙继续整改。
Windows 100%/125%/150%只记录实际可用环境，不修改用户系统缩放；未测明确待验。
方案审查不能代替实际运行视觉审查，AI接受不能写成用户认可。
