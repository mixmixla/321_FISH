## 连续授权与决策

主控可以在上述目标内自行核验最新源码、细化并冻结子任务、选测/实现/修复/独立审查、
按依赖衔接下一项，普通问题不用用户再复制Prompt。任务需用户决定时写出具体影响和可选方案。

不得因一项结束、对话变长或一次测试失败就结束整个Goal；修复先复测受影响项，保留首轮失败。

本批没有commit/push/PR/merge/发布、真实用户数据/设备、发Pro/外部消息授权；
保持已有账号UID/权限模型、协议兼容、管理员和文件鉴权及持久数据。不能自动扩至Roadmap其它方向。

## 代理与运行方式

当前额度为主控+2子代理。主控维护状态/文件归属/证据；一个核心实现者，另一个并行只读调查、
验证和独立审查。独立源码区域可以安排并行实现，涉及同核心文件时串行或独立worktree。
单模块最多一写入者，代理不能回滚他人修改，不能实现后自行验收。

Goal已启动，属于当前主控聊天；heartbeat自动化`321-fish`每30分钟回到同一聊天。
Goal正在推进时守护只核对，不能重复调度；守护不得绕过用户暂停、额度或系统预算。
无变化/无可行动项不反复报告，只在批次完成、失败、重要变化或需要明确决定时汇报。
本地执行需要电脑开启、应用运行、工作区可访问；不承诺关机/断网后仍持续。

## 验证节奏与交付

每项先有意义专项、调用链领域集成、独立代码/测试审查；本批结束形成最终候选时跑全量。
若子任务或重大变更明确需要更早全量，记录理由和对应版本；输入未变不机械重复同一报告。
进入下一项的依赖可明确为“上一项实现+领域+独立代码审查满足”，最终全量仍由批次终点统一验收。
子任务的完整通过结论不能超出其版本和证据；任何新代码变化使受影响旧结论需重核。

里程碑包保存批准范围、交付版本、实际增量、完成/未完成、测试矩阵与失败、运行证据、风险和待决事项。
