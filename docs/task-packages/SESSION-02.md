# SESSION-02 — 最后端退出与现有资源清理

版本v1，2026-10-01；范围来自 [BATCH-R1](BATCH-R1.md)，状态只见 [指挥中心](../AI_COMMAND_CENTER.md)。
依赖SESSION-01的实现、领域和独立代码审查满足；由主控核验后冻结具体函数并置READY。

目标：退出任一端只移除该Session；剩余同UID端仍在线、游戏玩家/传输/现有通话不被当成整账号离线。
最后一个端离线后才执行已有UID离线广播、房间玩家离开、传输/媒体会话清理，清理不重复。
核验已正确路径并补必要回归；只修可证实的清理顺序/条件缺口，不重写生命周期框架。

精确写入范围：`server.py:Hub.unregister`与仅实现同UID离线复查/现有资源清理的必要私有辅助，
新增`tests/test_session_cleanup.py`；唯一实现者`file_auth_impl`，独立审查`file_auth_review`。
不改web.py、client、games_pkg规则或现有文件/管理员鉴权；消息格式和稳定UID保持。
当前已确认非最后端也调用`_drop_xfers_of(sess.uid)`与`rooms.on_disconnect(sess.uid)`，
修复应把UID级清理置于最后端边界，而当前Session/token移除每端都需进行；不能简单提前return跳过token撤销。
持久身份/昵称映射、草稿/云历史/用户文件保留；不把注销当成删号，不迁移或删除真实用户数据。
不启用真实麦克风/摄像头，不修改账号规则或管理员踢人产品语义。

已确认锁释放后重登可让旧注销误清活端资源，须保持确认离线与UID内存清理的序列化边界，
不能仅捕获is_last后在无保护窗口清理。每端token撤销/closed标记、代表切换、重复调用与min_idle语义保持。
允许等价的“先原子完成旧离线再让新端加入”或“重登已加入则跳过旧UID资源清理”；
任何新端已接纳后创建的传输/游戏/语音房资源都不能被旧注销随后删除，不能误广播当前活端下线。
语音只清现有多人名册；现有1v1CALL仅信令转发，不新增call registry。
锁顺序和通知不得产生新的死锁，优先锁内内存快照/推进、锁外发送；必要的重新检查必须覆盖实际修改而非仅检查点。

验证矩阵包含TCP+Web和两个Web端，分别先注销一端、再注销最后端，重复注销与失效对象，
观察在线名单/通知/房间/传输/合成语音名册等对象是否只在正确边界清理；覆盖代表端、重复注销、min_idle复活与释放，
以及注销/重新登录受控交错下的新资源保护、管理员删除全部端的现有行为。
本任务不负责player_left终局、finish/Timer/客户端房间视图，保持Game任务精确边界。
