## 四、UI 美观升级：独立目标和硬性验收

可靠性优先修；视觉方向可先准备，在目标交互和状态明确后实施。允许明显重排界面和重做必要自绘组件，但沿用现有技术栈、发送/会话/游戏逻辑，不默认换框架重写项目。

### 1. 先拿出真正可看的设计

- 用真实截图分析旧界面的布局比例、阅读顺序、信息密度、字号/字重、颜色/对比度、间距、边框/阴影、图标和透明度问题。
- 给出 **两套有明显区别的视觉方向**，至少覆盖聊天主窗和游戏大厅的代表画面，使用高保真原型或实际 Tkinter 小范围实现展示，不只给文字说明或换色效果。
- 说明办公聊天、Excel 模式和两款棋类如何适配，兼顾实现成本、缩放与性能。主控推荐并选择一套推进；收到我的反馈时调整，不因没有逐项回复而停在展示方案。
- 建立统一设计规范与可复用样式来源：颜色、字体、间距、圆角、图标、组件及其状态，避免每页各自堆颜色和坐标。

### 2. 视觉方向与底线

- **现代、克制、清爽、有辨识度的 Windows 办公与休闲应用。** 聊天/设置以柔和中性色和少量统一强调色突出内容；游戏区可以适量活泼，组件语言保持一致。
- 改造陈旧默认控件、拼接式面板、杂乱渐变、过密边框和零散间距。减少大面积饱和色、无意义纹理、厚阴影和半透明穿透；不能保留旧观感，只替换几个图标。
- 中文与拉丁字体清晰协调，标题、正文、辅助信息层级稳定；间距可采用 4/8/12/16/24 节奏，圆角和阴影克制。数值服从实际内容密度和 DPI，不机械套模板。
- 核心工具采用统一风格、尺寸和线宽的图标，不用一排跨平台表现不一的 emoji 代替工具栏设计；emoji 可保留在消息内容和少量趣味元素中。
- 默认阅读区清晰、不依赖后方窗口颜色。透明风格作为明确可选效果，规则覆盖主窗和子窗，不降低文字、输入框和棋盘的可读性。
- 完整设计空态、加载、离线、等待、禁用、错误、成功、选中、hover、焦点和按下状态。弹窗、菜单、设置和错误提示也要有相同成品感。
- 办公界面以浅色为主，暗色如保留也必须可读。明确重点皮肤与兼容策略，不要求一次重做全部历史皮肤，但不能新增一套漂亮皮肤后放任默认入口仍然粗糙。

### 3. 重点页面

- **聊天：**合理分配会话列表、消息区、输入区；输入占主要空间，低频操作进入有名称的“更多”；清晰显示当前会话、连接、未读和发送状态，支持键盘操作。
- **登录与设置：**规则采用持续可见的标签/帮助/错误；设置按任务分组、对齐、留白。主动禁用热键和注册失败分开，减少猜图标的成本。
- **Excel：**保留真正可编辑的工作表、公式栏、会话记录和键盘行为；视觉贴近可信的现代办公工作簿。Enter 本地保存与 Ctrl+Enter 发送分开，发送目标清晰；提供合理适宽/换行/全文查看。不能改成不可编辑的装饰表格。
- **大厅：**两旗舰优先，增加搜索与必要人数/支持状态筛选；卡片封面、标题、说明和按钮层级统一。实验/未验证/本端不支持与地图对应，不用游戏数量充当成熟度。
- **棋盘与房间：**棋盘是视觉中心，玩家、执色、当前回合、观战/等待和不可操作原因清晰；统一两端配色和操作含义；最后一手、胜线、结算、上局摘要和再开入口易读易用，保持既有协议语义。
- **窗口：**主窗、游戏窗、专注窗、迷你条的收起/恢复/关闭/退出可发现且一致；关闭托盘和全局热键时仍能恢复与真正退出。

### 4. 视觉验收必须独立完成

- 同版本、同数据、同尺寸提供前后对比，覆盖登录、聊天/输入、设置、Excel、大厅、棋盘和结算；实际运行截图不能由原型图替代。
- 普通/最小/最大窗口及 Windows 100%/125%/150% 缩放按可用环境验证；检查裁切、重叠、比例、图标、换行、焦点、低对比度、空白和透明度。没有环境的项明确待验，不改用户系统缩放来凑证据。
- 视觉检查表单独审查整体成品感、层级、排版、配色、间距、组件一致性、状态完整和操作可发现性，有截图与具体结论；明显粗糙或不一致的页面继续改，不以功能测试通过代替。
- AI 可以作有限技术/视觉审查并迭代，但不能写成“用户认可审美”；交付我能直接查看的最终截图和本地运行入口。
