# 连续开发与换窗口接续

路线和当前位置看[任务清单](任务清单.md)；授权、状态、主控和下一动作只在[指挥中心](AI_COMMAND_CENTER.md)维护。
本指南不批准新的代码任务。Goal是单个聊天中的持续目标，跨聊天通过仓库文件恢复，再在目标聊天中启动或接续；
并不自动在项目内共享或迁移。依据：[OpenAI Goals文档](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)。

## 只需要知道的三件事

用户于2026-10-01明确表达的默认偏好：**后续开发按清单里的已批准有限批次，以Goal持续完成**。
这不是每个小任务单独开Goal，也不是批准整个Roadmap；每个批次只确认一次目标/范围/权限，随后自主推进到验收终点。

1. 用户确认一次有限批次：目标、范围、验收条件和操作权限。Codex在这个批次内拆解、实现、选测、审查、整改和衔接。
2. 普通问题不逐项等待用户；只有批次完成、重大设计/数据决定、需要外部权限或实际阻塞才交回用户。
3. 不把整个Roadmap变成无限Goal。批次完成就收口；新候选仍须批准，暂停/预算限制必须遵守。

## 在同一聊天持续进行

批次获准、前置条件具备后，按已记录的Goal默认偏好，以Task Package的完成条件启动Goal，不再逐个子任务询问。检查点至少保存：
Task ID/版本、base/head/branch/dirty、权限、主控聊天、文件所有权、完成/未完成、最近命令/真实结果、
活动进程/日志、待决问题和下一动作。长测试开始/结束、修改与审查交接都更新检查点。

Goal遇到普通测试或审查问题时继续在批准范围内整改；达到必测/独立审查条件才完成。
用户暂停后不能自行恢复，也不能借新聊天、新Goal或heartbeat绕过系统预算。Goal不是关机/断网后仍执行的保证。
不默认恢复已暂停的R1 heartbeat；确需定时守护时单独绑定当前有限批次，先核对旧进程，完成后停止。

## 换到同项目的其它 Codex 聊天

先读取：`AGENTS.md → COLLABORATION.md → docs/AI_COMMAND_CENTER.md → 当前Task/Review → PROJECT_MEMORY必要段落`。
然后核对实际Git HEAD/diff、当前批准范围、主控聊天、Goal状态和活动进程。保留已经验证的证据，不重启还在运行的测试。
主控查询使用聊天标题、项目目录、Task ID和Git基线交叉核对，真实聊天标识从本机工具查询，不复制进公开清单。
遇到同名或版本不一致时先保持只读核对，不依据模糊标题另起写入主控。

- 原主控仍在推进：新聊天只查看进度，不另起同一队列的实现、全量测试、Goal或守护。
- 原主控已停止且获准接续：根据检查点接管文件所有权，并在本聊天启动同批准范围的Goal。
- 原批次已完成：展示下一项与其前置条件，不把PROPOSED清单自动变为代码授权。
- 真正更换主控：由用户先在旧聊天明确暂停Goal并保存检查点，再让新聊天按文件接续。
  不能把仅打开另一个窗口解释成允许中断旧Goal或发送消息到其它聊天。

同一台电脑、同一项目目录可直接读这些文件；另一台电脑/远程checkout需要先获得同一版本文件。
当前未提交资料不能假设其它机器已经有。Pro聊天也不应被假定能读取本机文件；给它可访问的版本资料或用户提供的材料。

## 可直接使用的启动语句

### 继续一个已批准的批次

> 继续321_FISH。先按AGENTS和指挥中心恢复当前批准批次，核对原主控、Goal、Git版本和活动进程；不要重复开工。
> 确认可接续后，以Goal持续完成该批次的目标、验证、独立审查和交付记录，普通整改自主衔接，沿用记录中的权限。
> 如果原Goal仍活跃、批次已完成或没有READY任务，说明当前状态和下一审批点，不擅自扩大范围。

### 当前下一项：准备CC-02审查材料

以下是待用户确认的下一批启动模板，写在本指南中不等于已启动：

> 批准CC-02只读架构梳理批次，并以Goal完成审查材料：用户/UID/Session/token现状、持久历史/草稿/定时/云数据和文件归属、
> 当前已修项、剩余风险、最小兼容方案候选、禁止触碰边界、需Pro决定的问题和Task Package草案。
> 不修改应用代码或真实数据，不自动发Pro消息。材料自包含、绑定版本，独立资料审查通过后结束此Goal。

Pro审查最小方案、用户批准实现范围后，再为对应实现批次启动Goal。发送Pro消息、commit/push/PR、merge/release按各自授权。

## 阅读视图怎样更新

`AI_COMMAND_CENTER.md`的`BEGIN_ROADMAP_VIEW`至`END_ROADMAP_VIEW`之间是当前路线/进度的唯一源区块。
`docs/任务清单.md`从这个区块生成，保留源区块SHA256和基线；不手填第二套READY/ACCEPTED状态。
更新路线、进度或当前Goal时，先改指挥中心，再同步阅读视图并检查一致性。
本机生成辅助脚本不是状态来源；脚本不在另一机器时，可按两个标记复制源区块、计算UTF8 SHA256后生成同一视图。

旧M0–M6规划只保留在[历史档案](archive/任务清单_M0-M6_20260930.md)，不能用于自动调度。
